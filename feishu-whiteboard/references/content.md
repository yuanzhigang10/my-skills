# 把业务问题翻译成视觉表达

> 这是这套 skill 里**最不可替代**的一节。所有技术细节都可以查文档查 schema，但"画什么"决定一张图是不是值得看。

## 不要先画，先想

收到"帮我画个 XXX 图"时，先暂停 3 秒回答三个问题：

1. **核心信息是什么？** 一句话能说清的洞察是什么。如果说不清，说明用户自己也没想清楚——先帮 ta 厘清，再画。
2. **能不能一图胜千言？** 如果一张图传达不了关键洞察，分两张（或者干脆改成 markdown 表格）。
3. **视觉隐喻是什么？** 选与内容语义对应的几何形态，不要硬塞一种结构。

## 视觉隐喻清单（语义 → 几何）

| 业务语义 | 对应几何 | 推荐场景 |
|---|---|---|
| **层级 / 价值密度** | 金字塔 | 价值层级、需求层次、成熟度模型 |
| **循环 / 自驱** | 飞轮（同心圆 + 切割） | 增长闭环、PDCA、产品迭代 |
| **流失 / 转化** | 漏斗（向下收窄）| 用户旅程、销售转化、注册激活 |
| **因果 / 多维归因** | 鱼骨（主骨 + 分支）| 故障根因、问题分析、4M1E |
| **流向 / 分流** | 桑基（流条宽度编码） | 流量归因、能量流向、预算分配 |
| **辐射 / 中心展开** | 思维导图 / 辐射圆 | 概念展开、技能树、品牌矩阵 |
| **时间推进** | 横向时间轴 + 节点 | 路线图、历史大事记、版本迭代 |
| **依赖 / 调用关系** | 分层架构 + 跨层箭头 | 系统架构、技术栈、微服务依赖 |
| **从属 / 树状层级** | 组织架构图（top-down）| 团队结构、决策链、目录树 |
| **多维度对比** | 雷达图（多边形栅格）| 能力评估、产品对比、SWOT |
| **状态转换** | 状态图 | 订单状态、审批流、生命周期 |
| **同序协作** | 时序图 | API 调用、协议交互、握手流程 |

> **错配示例**：
> - 用流程图画"价值层级" → 没体现层级"压在底层"的支撑感
> - 用饼图画"四步流程" → 步骤之间是顺序，不是比例
> - 用思维导图画"组织架构" → 没体现严格的"父子上下级"

## 信息密度的边界

| 元素数 | 推荐表达 |
|---|---|
| 1-5 | 卡片网格 / 简单列表 + Lucide 图标点缀 |
| 5-15 | 一张主图（鱼骨/飞轮/路线图）+ 文字说明 |
| 15-30 | 分层架构 / 桑基 / 多面板拼图 |
| 30-80 | 拆成 2-3 张主题图（按"层""阶段""维度"切片） |
| 80-200 | 多张图 + 摘要表格补充；不要硬塞一张 |
| 200+ | 改用交互式表格 / 仪表盘（不是画板的强项） |

## 内容充实度的把握

**用户描述稀疏时**：用领域知识扩展信息维度。比如"画一个电商系统架构"——只有 6 个字，但你知道电商一定有：
- 流量来源（搜索 / 推荐 / 直通车 / 私域）
- 转化路径（落地页 / 详情页 / 加购 / 下单 / 支付）
- 后台（订单 / 库存 / 用户 / 物流）
- 数据（埋点 / BI / 模型训练）
- 基础设施（CDN / 数据库 / 消息队列 / 缓存）

把这些拓出来，再决定哪一层是用户关心的重点。

**但不要无限堆**：用户问"画 React 渲染流水线"，画到 Fiber 双缓冲就停了。画完整个虚拟 DOM diff 算法 + scheduler 内部 + lane 模型细节 → 反而抢夺了"流水线"的主题。

**判断标准**：每加一个元素，问自己"用户需要知道这个吗？" 如果不需要，删掉。

## 视觉层级（决定读图顺序）

人眼看一张图的顺序大概是：

1. **大字标题** —— 最先看到。这一句能不能成立？
2. **视觉锚点** —— 醒目的形状/颜色（黑色椭圆鱼头、中心圆、首尾节点）
3. **主体结构** —— 按布局自然引导（左 → 右、上 → 下、中心 → 辐射）
4. **细节标签** —— 看完结构后才看具体文字
5. **附属说明** —— 最后才读

设计时要**反过来**：先确定主信息走最显眼的位置，细节让位。

| 视觉权重技巧 | 例子 |
|---|---|
| 字号 | 标题 26+ / 卡片 16-18 / 标签 12-14 |
| 颜色对比 | 关键信息深黑色 `#1F2329` / 辅助信息中灰 `#646A73` |
| 形状大小 | CEO 200px 卡片 / 员工 140px |
| 边框粗细 | 主流程 2px / 弱依赖 1px |
| 填充饱和度 | 强调用满色 / 弱化用淡色或描边 |
| 位置 | 中心 > 边缘 / 顶 > 底 / 左 > 右（阅读起点）|

## 配色"少即是多"

每张图严格遵守：
- **3-5 套色系**（从 [`style.md`](style.md) 选）
- **同分组同色系**（人眼用色识别归属比识别形状快）
- **强调色克制**（黑色 `#1F2329` 一张图最多 2-3 处）
- **没有色板外的自创色**（"自创色" = 不专业的最大信号）

## "不专业的图"清单（自查表）

每完成一张图，按这表过一遍：

- [ ] 没有意义的渐变（彩虹色）
- [ ] 同一分组随机配色，分不出归属
- [ ] 字号同质化（全部 14px）
- [ ] 没有视觉锚点（全是浅色卡片）
- [ ] 标题太长 / 太短 / 太弱（应该 26+ bold，一行说完核心信息）
- [ ] 卡片网格无差异（每个卡片视觉权重都一样 → 用户不知道看哪）
- [ ] 连线斜成各种角度（缺乏秩序感）
- [ ] 字号 < 12（飞书画板缩放后不可读）
- [ ] 大量空白没利用（信息稀疏没扩展，或者全在角落）
- [ ] 一张图试图传达 > 1 个主洞察

任何一条命中，**就还没到能交付的程度**。
